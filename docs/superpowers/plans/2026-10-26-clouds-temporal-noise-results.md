# 体积云时域噪声 / 拖影 / 远地平线抖动 排查与修复结果（2026-10-26）

分支 `f2-reapply`。目标：把体积云的静止颗粒、拖动拖影、远地平线抖动对齐参考库
（three-geospatial storybook，本机 6006 常态化运行，可同 GPU 真机 A/B）。

## 一、计量方法（本轮确立，务必沿用）

1. **单对帧差不可用**：同配置复跑会给出 4.42 vs 1.67（2.3× 波动）。
2. **静止指标** = CDP `Page.captureScreenshot` 连拍 10 帧，算「逐像素时间标准差」在云区
   掩码（亮度>60 且 B−R≤18）内取均值。重复性 ±0.03。
3. **运动指标** = 页面内 `gl.readPixels` 逐帧读画布（rAF 内），连取 20–24 帧算逐像素时间
   标准差。比截图法灵敏，且能覆盖「旋转中」这种截图法测不到的场景。
4. **kymograph（时空图）** = 把连续帧的地平线带按「横轴=屏幕 x、纵轴=帧序号」叠成一张图：
   **竖条纹 = 图案锚定屏幕（不随世界移动，即用户感知的「噪点游移」）；
   斜条纹 = 图案随世界移动（正常）**。这是本轮定位远地平线问题的决定性工具。

## 二、根因与修复（按发现顺序）

| # | 根因 | 证据 | 修复 |
|---|---|---|---|
| 1 | 静止时 history 采样点逐帧抖动 | 关重投影后云区时间 std 5.6→1.35 | converge 档：静止关重投影 + 关裁剪 + EMA 1/32 |
| 2 | 纯旋转被误判为静止（`still` 只看位置） | 旋转时套用「静止关重投影」→ 拖影 | `still` 增加朝向判据（<1e-4 rad） |
| 3 | march 速度里恒定含 −jitter（射线抖动不进像素栅格） | 静止时 depthVelocity = (−0.00117, −0.00208)，应为 0 | resolve 侧 `prevUv = vUv − velocity − j(t−1)` |
| 4 | 几何抖动只作用于云射线 → 运动时云层相对地面晃 ±1.5px | 运动时 jitter=全幅 → 整体晃；=0 → 远地平线噪点游移 | 运动档缩放到 35%（±0.5px，亚像素） |
| 5 | 三态判断写错，35% 分支从未生效 | 三个对照 URL 表现完全一致 + 读 params 确认 jitter 恒 0 | 修正三态判断（`69a4963`） |
| 6 | **haze 的 alpha 在远地平线由逐像素场景深度驱动**，掠射角敏感度爆炸 → 屏幕锚定图案 | kymograph：开 haze 竖条纹 / 关 haze 斜条纹 | haze 在 >30km 淡出（近场空气透视效应；远场交给 atmosphere） |

## 六、2026-10-27 补轮：三个并存问题的共同根因（已根治）

### 根因（一句话）

`clouds.frag` 的射线重建用 `temporalJitter * resolution` 做窗口偏移，而 `czm_viewport` 是
**低分 FBO（320×180）**、`resolution` 是 **低分×4（1280）** → 射线位移被放大 4 倍：
N=4 时 ±1.5 **低分** texel = **±6 个全分像素**（three-geospatial 是 ±1.5 全分像素）。

同帧实测（`probe-ratio.mjs`，直接读 temporalJitter 与 depthVelocity）：

| 阶段 | velocity / temporalJitter |
|---|---|
| 修复前 | 恒 **4.00×** |
| 修复后（改用 `jitterPx = 低分 FBO 尺寸`） | **1.00×**（逐帧误差 <1e-5） |

这一条同时解释三个现象：
- **整体晃**：云射线整帧平移 ±6px，而地形（Cesium 自己渲染）不抖；
- **垂直噪点移动**：同一位移的 y 分量；
- **运动噪点增多**：±6px 的相位跨度让 16 相位平均退化成 3 低分 texel 的模糊，
  重投影误差也同比放大。

### 两处配套修复

1. **去抖动重采样**（`cloudsResolve.frag`）：低分 texel q 的真实采样位置是
   `(q+0.5)/lowRes + j(t)`，所以当前帧改用 `texture(colorBuffer, vUv − j(t))`，
   把整帧平移过的低分图重采样回**像素栅格**；`velocity` 在重投影前加回 `j(t)`
   （静止时精确为 0）。history 与 current 因此落在同一栅格上，EMA 才能长窗累积。
2. **统一档翻缺省**：`?cloudsUniform` 缺省改为统一（全程重投影 + 关裁剪 + EMA 1/32）。
   2026-10-26 该档被否决的「静止抖 + 拖动残影」正是「用上帧 j(t−1) 补偿」造成的
   （静止时 history 采样点 `p + j(t) − j(t−1)` 每帧游走）。

### 同构建 A/B（地平线带 256×48，1280×720，静止 20 帧 / 旋转 30°/s 20 帧 / 停后追平 12 帧）

| 配置 | 静止 std | 旋转 std | 停后追平 |
|---|---|---|---|
| 2026-10-26 缺省（jitter 4×、两套档） | 0.777 | 6.953 | 0.896 |
| 4× jitter + 去抖动 + 两套档 | 0.772 | 3.196 | 1.855 |
| **新缺省（jitter 1× + 去抖动 + 统一档）** | **0.462** | **1.363** | **0.282** |
| 新缺省 + `cloudsDejitter=0` | 2.280 | 3.196 | 1.855 |
| 新缺省 + `cloudsUniform=0`（两套档） | 0.462 | 2.252 | 0.426 |
| 新缺省 + `cloudsGeomJitter=0`（无抖动地板） | 0.211 | 1.402 | 0.140 |
| 统一档 + `cloudsClip=1`（AABB 裁剪） | 2.241 | 5.133 | 2.002 |

结论：去抖动重采样是主力（去掉它静止 0.46→2.28、追平 0.28→1.86）；统一档在运动与追平上
都优于两套档；**统一档下 AABB 裁剪必须关**（裁剪会把历史拉回当前帧噪声邻域 → 静止 2.24）。

### 新旋钮 / 逃生门

- `?cloudsDejitter=0` 回去抖动前的点采样（A/B 用）
- `?cloudsUniform=0` 回两套参数旧行为
- `?cloudsGeomJitter=0` / `?cloudsGeomJitterScale=`（现在缺省不再按 0.35 降幅，满幅 1.0）

### 坑（务必记住）

- **Cesium `removeComments()` 对「无换行的 `/** ... */` 块注释」会抛
  `TypeError: Cannot read properties of null (reading 'length')`**（`match(/\n/g)` 返回 null
  再取 `.length`），表现为**体积云整个创建失败**并被 demo 的 catch 报成「weather 纹理加载失败」。
  GLSL 里一律用 `//`。
- `windowCoord` 的实际位置在 **`CloudsMaterial.ts` 的 bridge 字符串**里，不在 `clouds.frag`
  （`clouds.frag` 只有 `uniform` 声明）——改射线重建别只改 `.frag`。
- 量纲自检工具：`tmp/probe-ratio.mjs`（同帧读 temporalJitter 与 depthVelocity，直接给倍率）。

## 七、2026-10-27 补轮二：拖影（用户反馈「只剩拖影」）

统一档（32 帧 EMA）在运动中没有任何边界：任何重投影误差都会沿拖动方向留 ~0.5s 残影。
三处改动（均可单独开关）：

1. **运动时开 AABB 裁剪**（静止仍关）：把历史夹在当前帧邻域内 = 有界无残影。
   实测副产品：运动画面里成片的孤立白点（= 卡在历史里的旧帧亮点）随裁剪消失。
2. **运动窗缩短**：`motionBlend` 缺省 1/32 → **0.25**（≈4 帧）。静止仍是 1/32（用户已验收）。
3. **远段长窗关闭**：`farBlend` 缺省 0.05 → **0**（>50km 的 20 帧窗是全场最长的拖影尾巴）。

**本机真 Chrome 实测（Apple Silicon，1280×720，地平线带）**

| 配置 | 静止 | 旋转 30°/s | 停后追平 |
|---|---|---|---|
| 上一版（clip 0 / α=1/32 / far 0.05） | 0.453 | 1.566 | 0.310 |
| 本版（clip 运动开 / α=0.25 / far 0） | 0.375 | 2.263 | 0.495 |
| 只缩窗不裁剪（clip=0 / α=0.25） | 0.349 | 2.142 | 0.339 |
| 只裁剪不缩窗（clip 开 / α=1/32） | 0.368 | 2.268 | 0.385 |

读法：旋转 std 的上升是「短窗少平均」的代价（不是新的伪影）；抓帧对拍（运动帧 vs 同机位收敛帧）
的云区 mean|Δ| 从 2.11 降到 1.92、p99 11.0→9.3，运动画面里的成片孤立白点消失。
kymograph（旋转中逐帧取一行叠图）在本版为干净斜条纹，无屏幕锚定的双轨。

**旋钮**：`?cloudsMotionBlend=`（0.03125=旧长窗 / 0.4=更短）、`?cloudsClip=0|1`、`?cloudsFarBlend=`。

## 八、2026-10-27 补轮三：静止时「垂直向上的粒子运动」

复现机位：`camera=29.8401,35.0481,4827,127.3,-16.7`（4827m 俯视云海）。

**来源分解（同机位，静止 20 帧，云区逐像素时间 std）**

| 配置 | stillStd |
|---|---|
| 缺省（相位轮换 + EMA 1/32） | 0.54（无 despeckle）/ 0.95（带 despeckle） |
| `cloudsGeomJitter=0` | 0.41 |
| `cloudsTemporal=0`（无 resolve → 相位也不轮换） | **0** |
| 冻结相位（`cloudsFrameUnfreeze=0`） | **0**，但画面满屏细点 |
| EMA 1/128 / 1/512 | 0.66 / 0.60（带 despeckle） |

结论：静止残留 = **STBN 相位轮换的平均残差**（不是拖影、不是重投影）。关掉 resolve 后
`marchFrame` 不再推进 → 图像逐帧逐位相同 → std 精确 0。但直接冻结相位会把**单相位锯齿**
烤进画面（截图实拍满屏点状），比轮换难看得多。加长窗收益递减（1/128 后趋平）。

**处置（两段式静止窗）**：停下先用 1/32 快收敛 `warmupFrames` 帧（约 0.3s，避免「停下糊
两秒」），之后切 **1/256** 长窗稳态；相位始终轮换（不烤锯齿）。

| 机位 | stillStd（前→后） | rotateStd | 停后追平 |
|---|---|---|---|
| 4827m 俯视 | 0.54 → **0.088** | 11.50（不变） | 0.086 |
| 146m 地平线 | 0.375 → **0.197** | 2.24（不变） | 0.42 |

**旋钮**：`?cloudsHoldBlend=`（稳态窗，缺省 0.00390625=1/256）、`?cloudsConvergeBlend=`
（收敛窗，缺省 1/32）、`?cloudsFrameUnfreeze=0`（完全冻结相位，仅诊断用）。

## 九、2026-10-27 补轮四：静止「云整体向上移动的残影」

用户反馈（`f99f948`，两段式静止窗）：静止时云整体向上移动、像残影。

**机理（结构性）**：`history_new(p) = history_old(p − δ)` 是平移算子。只要重投影每帧带
恒定微小偏置 δ（jitter 补偿残差 / 浮点精度 / 显卡差异），内容就按 δ/帧**累计爬行**；
EMA 窗越长拉回越弱（1/32 每帧拉 3%，1/256 只拉 0.4%）——把窗从 1/32 拉到 1/256，
等于把「看不出的偏置」放大成「看得见的整体移动」。

**修复**：静止时**一律关掉重投影**（不再区分 uniform 档）。静止没有相机运动就不存在需要
重投影的内容，prevUv 直接取像素自身 → 任何 velocity 偏置都不可能挪开历史采样点。

**踩坑**：曾想把 still 阈值 0.01m/1e-4rad 收紧到 0.002m/1e-5rad（防惯性拖尾被误判静止），
实测静止判定直接失效（相机矩阵有 mm 级抖动）→ 静止 std 0.088 恶化到 7.02。阈值不可再收紧。

实测（本机）：4827m 俯视 stillStd 0.088、rotateStd 11.44、追平 0.087；地平线 0.202/2.45。

## 十、2026-10-27 补轮五：高机位俯视云海的「运动颗粒」

用户反馈：`camera=29.9321,34.8424,6094,2.6,-16.8`（6094m 俯视）静止干净，但移动视角时
云层颗粒感强烈、颗粒随视角变化。同时确认「静止整体上移」已被第九节修复解决。

**定性**：不是新 bug，而是「运动窗 = 0.25（4 帧）」的直接代价——静止稳态窗 1/256，
运动窗只有 4 帧，逐帧 march 噪声只被平均 4 次就露出。

**本机对拍（同机位，移动截图）**：分别试了 clip 开关、α=0.25/0.10/0.05/0.04、N=2、
去抖动、despeckle、关云影、关光柱，云区高频能量全部落在 0.83–1.06（基线 0.86），
**没有一档能显著压下去**；唯一显著变差的是「关 clip + 长窗」(5.28 的 move-vs-settled，
= 拖影)。结论：在当前 march 噪声水平下，运动颗粒只能靠「更长窗」换，而更长窗立刻换回拖影。

**本轮处置**：恢复 `farBlend` 缺省 0.05（远段 20 帧窗）。2026-10-27 曾疑它造成拖影而关闭，
但同构建对拍显示它的追平 p99 反而更低（11.7 vs 24.3）——远云视差小，长窗安全。高机位
俯视时大部分云都在 >50km，这一档是唯一能压住远处云海的杠杆。

**留给用户的旋钮**：`?cloudsMotionBlend=`（0.1 ≈ 10 帧，颗粒更细；0.25 缺省）、
`?cloudsFarBlend=`（0.05 缺省）。

## 十一、2026-10-27 补轮六：俯视云海「颗粒感」的真杠杆（不是纹理 LOD）

用户怀疑是 LOD。逐项排除（6094m 俯视，短窗静止法直接量逐帧噪声）：

| 变量 | 逐帧噪声 std | 结论 |
|---|---|---|
| 缺省 | 2.83 | 基线 |
| `cloudsDetailLod=6`（detail 纹理 LOD 下限） | 2.84 | 无影响 |
| `cloudsWeatherBias=2`（weather mip 偏置） | 2.86 | 无影响 |
| `cloudsQuality=ultra`（更多 march 采样） | 2.84 | 无影响（甚至更细的抖动=更多噪声） |
| `cloudsQuality=low` | 2.32 | 略降 |
| `cloudsUpscale=2`（半分 march） | 2.38 | −16%，代价翻倍 |
| **`cloudsJitterScale=0.5/0.2/0.1/0`** | **2.71 / 1.91 / 1.43 / 0.95** | **正解：唯一 3× 级杠杆** |

结论：颗粒不是纹理 mip 造成的（纹理 mip 只影响形状模糊度），而是**march 步进抖动**
（startJitter + 逐样本相位）本身的逐帧去相关——采样点每帧换位置，逐帧结果就跳。采样
越多（ultra）反而噪声越大，正是这个机理的指纹。

**处置**：运动时把步进抖动降到 **15%**（静止保持满幅——静止有 1/256 长窗平均，且满幅抖动
可避免层边界「硬入口弧」）。`?cloudsMotionJitter=` 可调（1=关）。

实测：6094m 俯视 移动画面高频 0.86→0.72、肉眼颗粒明显变细且无条带/弧；静止 0.079（不变）、
146m 地平线 0.205 / 2.35（不变）。

## 十二、2026-10-27 补轮七：俯视云面「等高线阴影」（第 11 节改动的副作用，已回退）

用户反馈：俯视看云时云表面出现等高线状阴影，随离云距离变化上下移动。

**机理**：朝太阳光深 march 的**迭代步数**是 `remap(mipLevel, ...) - jitter` 取整
（`marchOpticalDepth`），靠 jitter 的 dither 把「步数跳变」摊成噪声。第 11 节把
`u_jitterScale` 降到 0.15 时，这一路的 dither 也一起被缩小 → 步数在固定 mip 处硬跳变 →
云面出现等高线状阴影，且随距离（mip 变化）上下移动。本项目 2026-09-29 已记录同族失效：
「jitter 归零 → march 步进驻波 → 等高线状二维云层」。

**处置**：
1. `motionJitterScale` 缺省回 **1**（不调制）——等高线消失，代价是运动颗粒回到第 11 节之前。
2. 朝太阳光深/BSM 两路改用**未缩放**的 `sunJitter`（新增局部量）——即使以后再把
   `?cloudsMotionJitter=` 调低，也不会再触发等高线，旋钮从此是安全的观感取舍。

实测（6094m 俯视，`cloudsMotionJitter=0.15`）：光深步进 dither 恢复，画面无条带/等高线。

## 十三、2026-10-27 补轮八：俯视云面噪点的「等距花纹」

用户：俯视看云表面很多噪点，离云远近变化时噪点呈等高线花纹变化。

**确认到的机制（已修）**：detail 层是**随机门控**——
`mipLevel*0.5 + (jitter-0.5)*0.5 < 0.5` ⇔ `jitter < 1 - mipLevel`，即应用概率 = `1 − mipLevel`。
在 mipLevel 0→1 的**等距过渡带**里，每个 march 采样点用抛硬币决定要不要 detail →
带内满噪点，且这条带是「到相机等距线」，相机高度一变就在云面上平移 = 用户描述的等高线花纹。

**修**：随机门控 → **平滑权重** `detailGate = saturate(1.0 − mipLevel)`（期望值相同、零随机性），
detail 随距离连续淡出。u_jitterScale=1 时形状与参考库一致，只是不再有噪点带。

**未闭环**：若该现象仍在，下一个嫌疑是 `mix(stepSize, maxStepSize, min(1.0, mipLevel))`
在 mipLevel=1 处的**导数拐点**（步长从 mix 切到 maxStepSize）——同样是 mip=1 等值线，
同样是随距离移动的环。判别：`?cloudsQuality=ultra` 若环纹消失=采样类；`?cloudsDetailLod=`
改 detail LOD 下限看噪点是否变。
